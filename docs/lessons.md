# 经验萃取（分批）

> 每完成一批题目，记录「踩坑 → 规则」的转化；目标是把一次性经验固化成仓库约定。

## 第 1 批：1-1 / 2-14 / 选做 2-1 / 3-1 / 2-7

### 1. 原作业代码不能直接搬

- 原报告代码普遍**读固定文件**（如 `TextFile2.txt`）、无输入校验、缺边界（n=0 / 空输入）；
- 规则：仓库统一 **stdin/stdout**，先补边界，再写文档。

### 2. 教材公式类题目：用「两种独立算法」互证

- 统计数字：逐位公式 vs 数位 DP（`tests/brute.py`）；
- Bell 数：Stirling 滚动 vs 组合数递推；
- 规则：能写两个独立实现就写两个；小 n 区域再叠加朴素枚举自检，三重保险。

### 3. 多解题目必须做语义校验

- LIS 的答案不唯一，逐字比会误报；`tests/checker.py` 只校验「长度正确 + 严格递增 + 是输入子序列」；
- 规则：凡是「输出任意可行解」的题，都必须配 checker，不允许用逐字比对。

### 4. 对拍抓到的问题（真实收益）

- LIS Python 版在 n=0 时 `tail_idx[-1]` 越界——样例没覆盖，随机对拍第 113 组抓到；
- 众数并列时报告没约定，主解与暴力必须显式统一「取最小」；
- 规则：`gen.py` 必须覆盖空输入与极端小值。

### 5. 编译器与工具链

- Windows 上无 g++；用 `winget install BrechtSanders.WinLibs.POSIX.UCRT` 得到 WinLibs；
- `shared/check.py` 自动查找 g++，找不到时仅跑 Python 并提示 `GXX`；
- 规则：CI 里用 ubuntu 的 g++，本地 Windows 用 WinLibs，`-O2 -std=c++17` 统一。

### 6. 成本观察（首批）

- 5 题 + 仓库骨架 + 工具链安装 ≈ 6.7M token（会话口径）；
- 其中读 16 份报告（PDF/OCR）约一半；代码与对拍占比不高；
- 结论：**读题成本 > 写码成本**，所以「先扫描题目、后精读」是高性价比策略。

## 第 2 批：3-4 / 4-1 / 4-7 / 5-3·选6-4 / 5-4 / 6-2 / 选 4-11

### 7. 分支限界的下界必须可采纳（本批踩坑）

- 顶点覆盖一题，最初用「每条未覆盖边取 min 端点权再求和」当下界；
- 反例：星形图中心权 1、两片叶权 100，两条边的 min 之和 2 > 真实最优 1 → **下界不可采纳，剪掉最优解**；
- 修正：取一组互不相邻的未覆盖边（极大匹配），每条匹配边至少要选一个端点，代价可相加且是下界；
- 规则：写分支限界前先自问「这个下界会不会超过真实剩余代价？」，并用暴力对拍验证。

### 8. 空输入 / 空容器是 C++ 的高发事故

- 顶点覆盖 m=0 时 `words=0`，内部数组长度为 0，选点分支越界 → 段错误；
- 规则：内部 bitset 行宽用 `max(1, words)`；`gen.py` 必须覆盖 m=0、n=1、k=n 等极端。

### 9. checker 要能接住「程序崩溃 → 空输出」

- 崩溃时 got 为空，checker 直接 `got[0]` 会抛 IndexError，掩盖真实原因；
- 规则：checker 首行先判空输出并给出「程序可能崩溃」的明确信息。

### 10. 浮点输出不要参与精确比较

- 服务次序题初版把平均等待四舍五入后与整数总等待相乘比较，引入误差；
- 规则：**先比整数总量**（总等待），浮点均值只做展示；比较时用 `round(x,2)` 与 0.011 容差。

### 11. 一题多解要「同题不同视角」

- 最小机器一题同时放回溯 / DP / 分支限界，题解里写清各自的适用规模与下界/状态设计；
- 运动员配对与工作分配同构（排列 + 权和）：状压 DP 与回溯互证，是复习最佳配对；
- 规则：同一题的多解尽量覆盖「搜索 vs 递推 vs 剪枝」三类思想。

### 12. 成本观察（第二批）

- 单题 ≈0.4–0.9M token，均值约 0.63M，约为首批的 1/2；
- 读报告的成本消失（题面已在记忆/文档里），主要花费在「写多解 + 修边界 + 写题解」；
- 每题的 checker/边界修复占 1–2 次返工，属于一次性成本。

## 第 3 批：选 5-13 / 选做 3-0 / 大作业 Travel

### 13. 一维 dp 的父指针在「状态会被覆盖」时不可靠

- 硬币问题用「二进制拆包 + 一维 dp + par[金额]=(物品, 上一金额)」还原方案，对拍抓到**同一个拆分物品被用两次**的假方案；
- 原因：`par[j]` 记的是金额而不是「某物品处理轮次中的状态」，中间状态被后续轮次覆盖后，回溯读到的是新版本；
- 规避：用二维层 DP（每层记录「用了几枚」）或单调队列（滑动窗口下界），本仓库改用单调队列作为主解；
- 规则：**要还原方案时，dp 层必须可追溯**（二维表/每层用量），一维 dp 只适合「只求值不求方案」。

### 14. 折半搜索的输出规模与空集约定

- 旅行规划要求输出**所有**组合，空集（target=0）会打印空行，与「去空白」的比对逻辑冲突；
- 约定：target ≥ 1，空集不是解；并在 checker 里按「方案集合」比对而不是逐行比对；
- 规则：输出集合类题目，先约定边界（空集/重复/顺序），再写 checker。

### 15. 成本观察（第三批）

- 选 5-13 约 0.6M；硬币问题 0.9M（含还原 bug 的排查与重写）；旅行规划 0.8M；
- 三题的共同点是「输出方案/集合」，checker 与边界约定的成本高于算法本身；
- 结论：**只要题目要求输出方案，测试成本 ≈ 算法成本的 1.5 倍**，预算时要把 checker 算进去。
