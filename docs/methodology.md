# 方法论：从作业到可复用题解的五步法

> 目标不是“把作业做对”，而是把每个题目变成**可迁移的算法资产**：换个数、换个问法、换到面试场景，依然能复用。

## 五步法

1. **读题建模**：先用自己的话重述输入、输出、约束，写出最朴素的枚举/搜索（暴力），确认样例能跑对。暴力解同时也是后续对拍的 oracle。
2. **找结构**：问三个问题——问题能否拆分（分治）？能否从小状态推大状态（DP）？每一步能否贪心且可证明（贪心 / 调度 / 交换论证）？搜索空间能否剪枝（回溯 / 分支限界）？
3. **推到目标复杂度**：从暴力出发逐级压缩：枚举 → 记忆化 → 维度削减 → 单调/前缀/二分/堆/树状数组等结构优化。每一级都要能说清“为什么少了哪些计算”。
4. **正确性论证**：对 DP 写出状态定义、转移、边界、归纳假设；对贪心给出交换论证或反例直觉；对剪枝说明下界/上界是紧的。
5. **对拍与文档**：样例 → 随机对拍（暴力 vs 优化，几百到上千组）→ 大规模计时；最后按模板写题解，把“踩过的坑”留在易错点小节。

## 优化检查单（每题收尾必须过一遍）

- [ ] 边界：n=0/1、空输入、全相等、全逆序、极值（如 10 的幂）；
- [ ] 溢出：`int` 够不够？乘法是否越界？Python 虽无溢出，但要让 C++ 通过同一用例；
- [ ] 重复/相等元素：严格递增还是非递减？
- [ ] 多解/多方案：题目要求“任一方案”还是“最优值”？
- [ ] 输出格式：行尾空格、空行、大小写；
- [ ] 性能：目标 n 下 C++ 运行 < 1s（对拍脚本会给出耗时）。

## 常见陷阱速查

| 陷阱 | 典型题目 | 规避方法 |
|---|---|---|
| 前导零 | 统计数字、删数 | 特判最高位，或从最高位贪心 |
| 0 计数特判 | 统计数字 | 公式对 d=0 单独推导 |
| 严格/非严格 | LIS | 二分用 `lower_bound` 还是 `upper_bound` 要对应定义 |
| 状态压缩顺序 | 状压 DP | 先枚举 mask 再枚举新增元素，保证前驱已算 |
| 贪心交换论证缺失 | 会场安排/服务次序 | 写清“任意最优解经交换仍不劣” |
| 剪枝上下界错 | 分支限界 | 下界必须可采纳（admissible），不能大于真实值 |
| 递归深度 | 回溯/分治 | n 大时改迭代或加大栈 |
| 文件路径 | 原作业读 txt | 统一标准输入输出，避免环境差异 |
